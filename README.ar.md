# powerk

تحكّم محلي في مشترك الكهرباء الذكي **MTTL-W01** من LG U+ / Jinheung (أربعة مقابس) —
من الهاتف، من الحاسوب، ومن أي مكان إذا شغّلت الخادم على VPS.

[English](README.md) | **العربية**

| | |
|---|---|
| الخادم | `powerk.py` — ملف واحد، بمكتبة Python القياسية فقط |
| التطبيق | `android/` — Kotlin + Jetpack Compose، Material 3 Expressive (حجم APK نحو 12 ميغابايت) |
| البروتوكول | بروتوكول المشترك نفسه `up:...` عبر المنفذ TCP **10086** |
| لا يحتاج | لا حساب سحابي، لا تطبيق مدفوع، **لا تغيير DNS أو DNAT في الراوتر**، لا فتح منافذ في المنزل، لا MQTT، لا Home Assistant، لا تفليش فيرموير، لا Docker |

## كيف يعمل

المشترك يتصل بنفسه بعنوان خادم يخزّنه في ذاكرته الداخلية. خطوة التهيئة (مرة واحدة)
تكتب **عنوان خادمك** في المشترك، وبعدها يفتح المشترك اتصال TCP مع
`<الخادم>:10086` ويتحدث ببروتوكوله النصي الخاص. `powerk.py` يجيب على هذا الاتصال،
ويحفظ الحالة اللحظية، ويقدّم واجهة ويب + واجهة JSON. تطبيق الأندرويد مجرد عميل لتلك
الواجهة.

```
الهاتف / متصفح الحاسوب ──► http://SERVER:8080 ──► powerk.py ◄── TCP 10086 ── المشترك
                                                      │
                                          تطبيق الأندرويد (http://SERVER:8080/api/...)
```

لأن المشترك هو الذي يبدأ الاتصال **إلى الخارج**، لا تحتاج فتح أي منفذ في راوتر
المنزل، ونفس الخادم يعمل على شبكتك المحلية أو على VPS بعنوان عام.

طريقتان للتشغيل:

* **الوضع أ — محلي**: يعمل `powerk.py` على حاسوب أو Raspberry Pi داخل شبكتك.
  الواجهة متاحة من شبكتك فقط.
* **الوضع ب — خادم**: يعمل `powerk.py` على VPS بعنوان عام. المشترك يتصل بالـ VPS
  من المنزل، وتتحكم به من أي مكان باستخدام الرمز (token).

الوضعان يستخدمان نفس الملف ونفس التطبيق.

## الخطوة 0 — تهيئة المشترك (مرة واحدة، للوضعين)

التهيئة تُخبر المشترك شيئين: أي شبكة واي فاي ينضم إليها، وأي عنوان خادم يتصل به.
وتتم عبر نقطة الاتصال الخاصة بالمشترك.

1. **شغّل الخادم** على الجهاز الذي سيبقى قيد التشغيل، وسجّل العنوان الذي يطبعه:

   ```bash
   python powerk.py
   ```

   ```
   powerk
     web UI (phone/PC)  http://192.168.1.14:8080
     strip server       TCP 10086
     auth               NONE - only safe on a trusted LAN
   ```

2. **أدخل المشترك في وضع الإعداد**: اضغط زرَّه الرئيسي مع الاستمرار نحو 10 ثوانٍ
   حتى يبدأ مؤشر LED بالوميض السريع.

3. **اتصل بشبكة المشترك** من الجهاز الذي سينفّذ أمر التهيئة:
   الشبكة `TONLY_TAP_XXXXXXX`، وكلمة المرور `LGU_XXXXXXX` — نفس الأحرف السبعة التي
   تأتي بعد `TONLY_TAP_`. عدم وجود إنترنت في تلك الشبكة أمر طبيعي.

4. **نفّذ التهيئة** — استخدم عنوان الخطوة 1 (الوضع أ) أو عنوان الـ VPS العام (الوضع ب):

   ```bash
   python powerk.py provision --ip 192.168.1.14 --ssid "YOURWIFI" --password "YOURWIFIPW"
   ```

   النتيجة المتوقعة:

   ```
     up:ip:ip_ok
     up:connect:connect_ok
   ```

   بروتوكول المشترك لا يقبل الرمز `:` أو أسطرًا جديدة داخل اسم الشبكة أو كلمة
   المرور؛ الأمر يرفض بدل أن يفشل بصمت. ويجب أن يكون `--ip` عنوان IPv4 صحيحًا.

5. **أعِد الجهاز إلى شبكتك العادية.** خلال ثوانٍ يتصل المشترك بـ `<ip>:10086`
   ويظهر في الواجهة.

6. **تحقّق** من سجل الخادم:

   ```
   [device] MTTL 91C0C4C model=lgutap fw=0.1.54-1.0.66
   ```

لنقل المشترك إلى خادم آخر لاحقًا: أعِد الخطوة 0 بالعنوان الجديد — المشترك يخزّن
عنوان خادم **واحدًا** فقط.

### إذا كان الجهاز بلا واي فاي

جهاز الخادم لا يحتاج واي فاي لـ **تشغيل** powerk — سلك الشبكة يكفي، فالمشترك يحتاج
الوصول إلى عنوانه فقط. الواي فاي مطلوب مرة واحدة لخطوة التهيئة، ومن أي جهاز يستطيع
الاتصال بـ `TONLY_TAP_XXXXXXX` وفتح TCP إلى `192.168.1.1:30300`:

1. **هاتف أندرويد، مجانًا** — على واي فاي المنزل ثبّت
   [Termux](https://f-droid.org/packages/com.termux/)، ثم `pkg install python`،
   ثم نزّل السكربت بـ `curl -O http://<عنوان-الخادم>:8080/powerk.py`، وبعدها اتصل
   بشبكة المشترك ونفّذ أمر التهيئة أعلاه (بعنوان **الخادم**).
2. **أي تطبيق "TCP client"** — اتصل بشبكة المشترك، ثم اتصل بالعنوان `192.168.1.1`
   والمنفذ `30300` وأرسل السطرين التاليين، كل واحد في اتصال مستقل، بنهاية سطر CRLF:
   ```
   up:ip:<SERVER-IP>                ->  up:ip:ip_ok
   up:connect:<SSID>:<PASSWORD>     ->  up:connect:connect_ok
   ```
3. **وصلة واي فاي USB** (بنحو 10 دولارات) على جهاز الخادم — ثم اتبع الخطوة 0 عادة.
4. **حاسوب مستعار لدقيقتين** — نزّل `powerk.py` من
   `http://<عنوان-الخادم>:8080/powerk.py` ونفّذ نفس الأمر بعنوان **الخادم**، لا
   بعنوان الحاسوب المستعار.

تطبيق `MTTL-W01-Provisioner.apk` المرفق لا يصلح لهذه الخطوة: فهو يخزّن بيانات
الواي فاي فقط، ولا يخزّن عنوان خادم.

## الوضع أ — محلي (داخل شبكة المنزل)

1. على الحاسوب أو Raspberry Pi:

   ```bash
   python powerk.py                 # prints http://<ip>:8080
   ```

2. اهيّئ المشترك بذلك العنوان (الخطوة 0 أعلاه).

3. افتح `http://<ip>:8080` في أي متصفح على نفس الشبكة — أربعة أزرار للمقابس،
   تشغيل/إيقاف الكل، الواط اللحظي، الكيلوواط ساعة، الحرارة، الجهد، وقوة الإشارة.

4. في تطبيق الأندرويد: **الإعدادات ← عنوان الخادم** = ذلك العنوان، المنفذ `8080`،
   والرمز فارغ ← **حفظ** ← **اختبار** ← `متصل · 1 مشترك، 1 متصل`.

ملاحظات:

* أعطِ الجهاز **عنوانًا ثابتًا** (أو حجز DHCP) — المشترك يتذكر العنوان الذي هيّئته
  به، وتغيّر العنوان يعني إعادة الخطوة 0.
* يجب أن يبقى الجهاز مستيقظًا؛ والمشترك يعيد الاتصال تلقائيًا بعد النوم أو إعادة
  تشغيل `powerk`.
* جدار حماية ويندوز: اسمح للطلب الخاص بـ Python عند أول تشغيل، أو نفّذ:
  ```powershell
  netsh advfirewall firewall add rule name="powerk" dir=in action=allow protocol=TCP localport=8080,10086
  ```

## الوضع ب — خادم VPS (تحكم من أي مكان)

المشترك يتصل بالـ VPS من المنزل، وأنت تصل إلى الواجهة من أي شبكة.

### 1. انسخ الخادم

```powershell
scp X:\powerk\powerk.py ubuntu@<VPS-IP>:~/powerk/
```

### 2. شغّله كخدمة systemd

```bash
cd ~/powerk
TOKEN=$(openssl rand -hex 16); echo "YOUR TOKEN: $TOKEN"     # احفظ هذا الرمز
PUB=$(curl -s https://api.ipify.org)                          # عنوان IPv4 العام
sudo tee /etc/systemd/system/powerk.service >/dev/null <<EOF
[Unit]
Description=powerk MTTL-W01 server
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/home/ubuntu/powerk
ExecStart=/usr/bin/python3 /home/ubuntu/powerk/powerk.py serve --ip $PUB --web-port 7896 --token $TOKEN
Restart=always
RestartSec=3
User=ubuntu

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now powerk
curl -s -o /dev/null -w 'local code: %{http_code}\n' http://127.0.0.1:7896/     # 401 = يعمل والرمز مفعّل
ss -lntp | grep -E '7896|10086'
```

عدّل `User=` و `WorkingDirectory=` والمنفذ حسب إعدادك. المنفذ `7896` مجرد مثال،
أما `--port 10086` فلا يمكن تغييره أبدًا (فيرموير المشترك يتصل بـ 10086).

### 3. افتح المنافذ

في جدار الحماية/مجموعة الأمان لدى مزوّد الـ VPS (وفي `ufw` إن كنت تستخدمه):

| المنفذ | الغرض | من يصل إليه |
|---:|---|---|
| **10086/tcp** | المشترك | الإنترنت (المشترك يتصل من عنوان منزلي متغيّر) |
| **7896/tcp** | واجهة الويب و API | أنت — ويفضل أن يكون عبر VPN/نفق، انظر أدناه |
| 22/tcp | ssh | أنت |

تحقّق من حاسوبك:

```powershell
Test-NetConnection <VPS-IP> -Port 10086
Test-NetConnection <VPS-IP> -Port 7896
```

### 4. اهيّئ المشترك بالعنوان العام

في المنزل، اتبع الخطوة 0 مع `--ip <VPS-IP>`، ثم راقب الـ VPS:

```bash
journalctl -u powerk -f      # [device] MTTL 91C0C4C model=lgutap fw=0.1.54-1.0.66
```

### 5. الاستخدام

* **التطبيق**: الإعدادات ← المضيف `<VPS-IP>`، المنفذ `7896`، والرمز ← حفظ ← اختبار.
* **المتصفح**: `http://<VPS-IP>:7896/` ← اسم المستخدم `powerk` وكلمة المرور هي
  الرمز (أو افتح `http://<VPS-IP>:7896/?t=TOKEN` مرة واحدة).

### إبقاء الواجهة خاصة (اختياري لكن مستحسن)

احمِ منفذ الجهاز ومنفذ الواجهة معًا. بروتوكول TCP الخاص بالمشترك لا يدعم المصادقة
أو التشفير، ويمكن لعميل انتحال عنوان MAC وإرسال قراءات مزيفة. يرفض الخادم اتصالًا
ثانيًا لنفس الجهاز أثناء اتصال الجلسة الحالية، لكن ذلك لا يثبت هوية الجهاز.
أبقِ المنفذ 10086 داخل شبكة موثوقة أو اربط شبكة المنزل بالخادم عبر VPN؛ المشترك
نفسه لا يشغّل عميل VPN. إذا اضطررت لفتحه للعامة، قيّد عناوين المصدر في الجدار
الناري حيثما أمكن، وحدّد الأجهزة المعروفة:

```bash
python powerk.py serve --token YOUR_TOKEN --allow-device AABBCCDDEEFF
```

يمكن تكرار `--allow-device` لعدة أجهزة. بدونه يسمح الخادم بتسجيل أي MAC لتسهيل
الإعداد المحلي. القائمة ليست مصادقة: من يعرف MAC مسموحًا يستطيع انتحال الجهاز
عند انقطاعه. عدد الاتصالات محدود، وتُغلق جلسات الأجهزة التي لا تستجيب.

* **الرمز** (`--token`) — مطلوب لكل صفحة وكل طلب API. بدونه تكون الواجهة مفتوحة
  لأي شخص يجد المنفذ.
* **VPN / نفق** بدل فتح المنفذ: ثبّت [Tailscale](https://tailscale.com) على الـ VPS
  وعلى هاتفك، ثم استخدم عنوان `100.x.y.z` في التطبيق وأبقِ منفذ الويب مغلقًا
  (`ufw allow in on tailscale0 to any port 7896 proto tcp`). لا شيء مكشوف، والاتصال
  مشفّر.
* بروتوكول HTTP غير مشفّر يعني أن الرمز مرئي لأي طرف على مسار الشبكة. إن كان ذلك
  يهمك، ضع nginx/Apache أمامه كوسيط HTTPS عكسي (أو استخدم خيار الـ VPN أعلاه).
  استخدم `--web-bind 127.0.0.1` للخادم الخلفي، وفعّل HTTPS في إعدادات التطبيق
  مع اسم المضيف ومنفذ الوسيط. يجب أن تكون شهادة الخادم موثوقة.

يختار `--device-bind` عنوان الاستماع للأجهزة. أما `--ip` فيغيّر العنوان المعروض
في الواجهة وتعليمات الإعداد فقط. التطبيق يخفي الرمز ويعطّل النسخ الاحتياطي،
ويستطلع الحالة أثناء ظهور التطبيق فقط.

طلبات التحكم تتطلب MAC من 12 خانة سداسية، ورقم مقبس صحيحًا من 0 إلى 4، وقيمة
JSON منطقية لـ `on`؛ النص `"false"` مرفوض. الحد الأقصى للطلب 4 KiB. لا يُؤكّد
النجاح إلا عندما تبلغ جميع المقابس المطلوبة عن الحالة المطلوبة. الرمز 502 يعني
أن الحالة لم تُؤكّد، و503 أن الجهاز غير متصل، و504 انتهاء المهلة. مهلة الأمر
ثماني ثوانٍ وتشمل الانتظار؛ الإلغاء لا يتراجع عن أوامر أُرسلت بالفعل، فحدّث
الحالة قبل إعادة المحاولة. تتضمن الحالة `last_seen` بتوقيت Unix لآخر تقرير كامل.
تُعرض أخطاء الاتصال في الويب وتُعطّل الأزرار أثناء التنفيذ وعند انقطاع الجهاز.

للتحقق محليًا:

```bash
python -m unittest discover -s tests -v
python powerk.py selftest
node --test tests/web_ui.test.cjs
cd android
./gradlew testDebugUnitTest lintDebug assembleDebug
```

يشغّل CI اختبارات Python على 3.8 و3.12، واختبارات الويب على Node 20، واختبارات Android وlint وبناء APK
باستخدام JDK 17 وSDK 37، ثم يرفع التقارير وملف APK. لا تتطلب الاختبارات جهازًا
حقيقيًا؛ تستخدم اتصالات محلية وهمية. لا يوجد ملف API مولّد؛ عند تغيير العقد
حدّث العملاء والاختبارات ومرجع API في الوثائق.

## تطبيق الأندرويد (`android/`)

```bash
cd android
gradlew assembleDebug            # أو افتح المجلد في Android Studio
```

التثبيت على الهاتف:

* الأسهل — والخادم يعمل، افتح `http://<الخادم>:<منفذ-الويب>/powerk.apk` على الهاتف
  (الخادم يقدّم ملف APK المبني، وهذا العنوان لا يحتاج رمزًا)، أو
* `adb install android/app/build/outputs/apk/debug/app-debug.apk`

ما ستحصل عليه: شاشة بداية متحركة، حلقة قدرة حيّة (واط + كبسولات الطاقة/الجهد/التيار/
الإشارة)، أربعة مقابس متحركة كل واحد بمفتاح داخلي، زر تشغيل/إيقاف الكل، حالات
الانقطاع والأخطاء، تنبيهات عند فشل الأوامر، وشاشة إعدادات فيها عنوان الخادم والمنفذ
والرمز واختبار اتصال ومبدّل اللغة.

تفاصيل السلوك:

* يسأل `/api/state` كل ثانيتين؛ وعند الضغط يتغيّر لون المقبس فورًا ويظهر مؤشر دائر
  مكان المفتاح حتى يرد المشترك.
* تُمنع الأوامر على المقبس نفسه أثناء تنفيذ أمر آخر — لا تكرار عشوائي.
* **اللغات**: العربية والإنجليزية، وتتبع لغة الهاتف تلقائيًا، ويمكن تغييرها من
  الإعدادات (وتظهر أيضًا في قائمة لغة التطبيق داخل إعدادات أندرويد).
* نسخة debug بدون توقيع — مناسبة للاستخدام الشخصي، لا لمتجر Play.

## واجهة الويب و API

| الطريقة | المسار | ملاحظات |
|---|---|---|
| GET | `/` | واجهة الويب |
| GET | `/api/state` | `{"local_ip":"…","port":10086,"devices":[{"mac","name","model","fw","online","on","power_w","energy_kwh","voltage","current_a","rssi","outlets":[…]}]}` |
| POST | `/api/onoff` | `{"mac":"…","outlet":0-4,"on":true}` — المقبس `0` يعني الكل |
| GET | `/powerk.py` | السكربت نفسه (عام) |
| GET | `/powerk.apk` | تطبيق الأندرويد المبني، إن وُجد (عام) |

عند استخدام `--token`، كل طلب يحتاج الرمز — بأي طريقة من:

* ترويسة `X-Token: TOKEN` (ما يرسله التطبيق)
* HTTP Basic، المستخدم `powerk` والرمز ككلمة مرور (ما يفعله المتصفح)
* معامل الاستعلام `?t=TOKEN`

يبقى `/powerk.py` و `/powerk.apk` عامَّين عن قصد، حتى يستطيع هاتف جديد تنزيل
التطبيق، ويستطيع جهاز بلا واي فاي تنزيل أداة التهيئة.

## مرجع البروتوكول

صيغة الرسائل التي يتحدثها المشترك على TCP 10086 :

| الاتجاه | الرسالة |
|---|---|
| المشترك ← الخادم | `up:bootinfo:<model>;<mac>;<mac>;<fw>;connect` |
| المشترك ← الخادم | `up:getinfo:<ch>:<runtime>;<relay on/off>;<state>;<overload>;<overheat>;<power mW>;<energy hex Wh>;<prev hex>;<config hex>;<status>;<event hex>;<temp C>` ×4 |
| المشترك ← الخادم | `up:power_report:<ch>:<mV>` (≥50000) أو `:<mA>` |
| المشترك ← الخادم | `up:query:<rssi>` |
| المشترك ← الخادم | `up:event:onoff:<1-4>:on\|off` (الزر الفيزيائي، و `0` = الكل) |
| الخادم ← المشترك | `up:getinfo:all`، `up:onoff:<1-4>:on\|off`، `up:power_report:1:vol`، `up:query:wifirssi` |
| نقطة الإعداد `192.168.1.1:30300` | `up:ip:<ip>` ← `up:ip:ip_ok`، و `up:connect:<ssid>:<pw>` ← `up:connect:connect_ok` |

لا يوجد أمر `up:onoff:0`؛ "الكل" يُرسل كحلقة على المقابس 1 إلى 4. بعض الرسائل تأتي
مبطّنة ببايتات NUL، والمنفذ ثابت على 10086.

## حل المشكلات

| العَرَض | السبب / الحل |
|---|---|
| `Not reachable` أثناء التهيئة | الجهاز غير متصل بـ `TONLY_TAP_*`، أو المشترك ليس في وضع الإعداد (أعد الضغط على الزر) |
| لا يظهر المشترك في التطبيق/المتصفح | يجب أن يكون المشترك على 2.4 غيغاهرتز؛ ويجب أن يكون العنوان الذي هيّئته ما زال عنوان الخادم؛ راقب أسطر `[device]` أو `journalctl -u powerk -f` |
| كان يعمل ثم توقف | تغيّر عنوان الخادم، أو نام الجهاز، أو انتقل المشترك إلى شبكة أخرى ← أعد الخطوة 0 |
| المشترك يتصل ثم ينقطع | بعض التقطيع طبيعي ويعيد الاتصال؛ إن لم يستقر فتحقق من قوة الإشارة (`rssi`) ومن أن نسخة واحدة فقط من `powerk` تعمل |
| `bad request` من الـ API | نسخة تطبيق قديمة كانت ترسل جسمًا فارغًا — حدّث ملف APK |
| التطبيق ينهار عند الفتح | حدّث إلى أحدث APK (نسخ قديمة كان فيها خطأ فهرسة المقابس) |
| الواجهة لا تُفتح لكن 10086 يعمل | منفذ الويب غير مفتوح، أو شبكتك لا تصل إلى الـ VPS |
| لا شيء يستجيب إطلاقًا | `python powerk.py selftest` يثبت منطق الخادم بدون أي عتاد |
